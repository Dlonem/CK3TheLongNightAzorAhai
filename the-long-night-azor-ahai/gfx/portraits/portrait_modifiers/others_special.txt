# Ereska, KngZawd, CinkoSenpai: after AGOT's 0.5.1 update, LIVING characters -- women above all -- rendered
# with the corpse look. Our appliers were keyed on the trait alone, and trait references in a mid-update save
# are exactly the thing that drifts when any mod in the playset adds or removes traits. Every undead-look
# entry now also requires one by-NAME marker that conversion stamps and drift cannot fake:
# ln_one_of_them (stamped at every creation/conversion site since 1.0.7), the Others' house, or an undead
# government. A living character who "gains" the trait through save drift now renders as what she is -- a
# living character. A genuine pre-1.0.7-save wight missing all markers renders alive until the heartbeat
# re-stamps it (mutate_into_other_effect backfill, 1.0.15) -- the mild failure, chosen deliberately.

	usage = game

	priority = 10

	others_eyes_1 = {
		dna_modifiers = {
			accessory = {
				mode = modify
				gene = eye_accessory

				value = 0.5
			}
			accessory = {
				# 1.0.11 -- WAS `mode = modify`, AND THAT IS WHY THE OTHERS HAD EMPTY SOCKETS.
				# CK3: "modes modify, modify_multiply and replace only work for regular genes."
				# others_eye_accessory is declared under special_genes, so it is a SPECIAL gene and modify
				# is rejected -- error at dnamodifier.cpp:50, three hits, one per entry below.
				# The eye_accessory/no_eyes block above does NOT error, because vanilla's eye_accessory is a
				# regular gene. So the removal was applying and the replacement was not: eyes deleted, glow
				# never added, and every Other and wight rendered with black holes.
				# `add` is the accessory mode -- 2,131 uses in vanilla, 2,686 in AGOT, against 9 and 11 for
				# modify. Leave the no_eyes block alone; it is doing its job.
				mode = add
				gene = others_eye_accessory
				template = others_eyes
				range = { 1 1 }
			}
